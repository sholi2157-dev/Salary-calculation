## S-CUR-04 — אסימון refresh של OAuth אינו קשור ללקוח ואינו מוגן מפני שימוש חוזר

- חומרה **Medium**, עדיפות **P1**; שרת OAuth/MCP. מאומת דטרמיניסטית בקוד האמיתי עם Firebase מדומה; `assistant-proof`.
- `assistant.cjs:382–389`: הבקשה נבדקת רק באמצעות פתיחת token והענקה פעילה. `client_id` אינו נבדק; גם הזהות `c` נגרעת מהנתונים לפני יצירת refresh token. אין רשומת סבב, ביטול predecessor או sender binding. אסימון חדש נוצר אבל הישן תקף במקביל.
- שחזור מבודד: חילוף code תקין עם PKCE עבור לקוח A; להשתמש ב־refresh_token פעמיים עם client_id של B. שתי הבקשות מחזירות 200. פלט הבדיקה אינו כולל אסימונים.
- צפוי: לקוח ציבורי מקבל refresh token הקשור לזהותו, עם rotation/reuse detection או מנגנון sender-constrained מתאים. בפועל העתק ישן ממשיך להנפיק access tokens עד תום ההענקה או ניתוקה; בהענקה 'עד שאנתק' אין תאריך סיום.
- גבולות: אין כאן פריצה לחשבון ללא אסימון. scope והגבלת uid עדיין נאכפים, ניתוק grant עדיין נבדק בכל בקשה, AES-GCM תקין מבחינת מבנה. הממצא נוגע להקטנת הנזק במקרה של דליפת refresh token ולהתאמת OAuth המוצהרת, לא לטענה שנגנבו אסימונים.
- תיקון: לשמר client binding, לבדוק client_id, משפחת refresh/מספר דור אטומי עם זיהוי reuse וביטול משפחה; לתכנן טיפול בבקשות refresh מקבילות. מורכבות בינונית־גבוהה; סיכון נסיגה בינוני־גבוה בחיבורי לקוחות קיימים, נדרש מעבר תואם או חיבור מחדש מוסבר.
- רגרסיה: wrong client, predecessor replay, שני refresh מקבילים, ניתוק/קיצור grant, expiration, לוקלי ולקוחות אמיתיים מאושרים. קוד שרת זהה בבסיס הציבורי.

## המלצות בלבד ומגבלות

CSP ו־frame-ancestors לדף הענקת OAuth הם הקשחה מומלצת P2/P3 (עם בדיקת תאימות לקוחות); היעדרם אינו ניצול מוכח. להגביל גודל/סכמת מסמכי Firestore באופן תואם, לבחון קצב/זיכרון batch MCP ולוודא idempotency לפני הרחבת שימוש. הרשאות Firebase וקונפיגורציית MCP בייצור לא נקראו. לא התבקשו/נחשפו credentials. אין בדיקת ניצול ייצור, מכשיר, UI חי או חיבור OAuth אמיתי. כל אלה נשארים שערי שחרור לפי הסיכון.

בדיקה שנייה חזרה על ההבחנות: קוד חשבונות פעיל עכשיו; הורדת RC אינה אמורה להיות ציבורית עדיין; fallback ישן הוא כשל נפרד; log failure אכן מונע Undo; replay אינו גישה ללא token; נוסחת CSV לא הורצה חיצונית. מאגר המקור לא שונה.
