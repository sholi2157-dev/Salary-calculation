# חישוב שכר 2.0 — תוכנית טכנית לאנדרואיד (טיוטה לאישור)

סטטוס: טיוטה, 2026-10-16. שום שינוי קוד לא בוצע. כל שלב מתחיל רק באישור הבעלים.
בסיס: `codex/android-local-distribution` ב-`bb72a09` (RC16, versionCode 24). Room גרסה 8. `MainActivity.kt` כ-6,000 שורות.

## עקרונות שלא משתנים
- אותה חבילה, אותה חתימה, versionCode עולה בלבד (2.0-rc1 = 25).
- מיגרציה מוסיפה בלבד. אין מחיקה או שינוי של עמודות קיימות, אין `fallbackToDestructiveMigration`.
- סכומים שמורים לא מחושבים מחדש לעולם.
- כל RC חתום עובר עדכון אמיתי מ-RC16 עם נתונים סינתטיים שמכסים את כל סוגי הרשומות, ובדיקת יומן קריסות.
- עבודה בענף חדש `claude/v2-android` שנפתח מענף ההפצה. שום מיזוג לענף ההפצה בלי אישור.

## 1. מודל הנתונים — Room 8 → 9
### `work_entries` (קיימת) — עמודות חדשות עם ברירות מחדל
| עמודה | סוג | ברירת מחדל | למה |
|---|---|---|---|
| `kind` | TEXT NOT NULL | `'shift'` | `'shift'` / `'job'` (קבלנות) |
| `payKnown` | INTEGER NOT NULL | `1` | 0 = תעריף חסר (משמרת) או סכום חסר (קבלנות). השדות `hourlyRate`/`totalEarnings` נשארים NOT NULL ומכילים 0 כשלא ידוע — ולכן כל חישוב חייב לבדוק `payKnown` |
| `bonus` | REAL NOT NULL | `0` | הבונוס שלי. כבר כלול ב-`totalEarnings` |
| `entryUid` | TEXT | ממולא ב-UUID במיגרציה | זיהוי יציב לסנכרון עתידי ולמניעת כפילויות |
| `seriesKey` | TEXT NULL, UNIQUE | NULL | `seriesId@date` למשמרת שאושרה מסדרה. האינדקס הייחודי מונע כפילות גם בהרצה כפולה |
| `autoConfirmed` | INTEGER NOT NULL | `0` | "נרשמה לבד" |

- שעות בלבד ("ידני") — כמו היום: `isTimeRange = 0`.
- קבלנות — `kind='job'`, `isTimeRange = 0`, `hours` = הזמן אם נמסר, אחרת 0.
- בונוס לכל עובד במשמרת קבוצתית — שדה `bonus` נוסף בתוך `groupWorkersJson`. RC16 מתעלם משדות לא מוכרים שם.

### טבלאות חדשות
- `shift_series` — `id` (UUID), קטגוריה, ימים (bitmask), התחלה, סיום, תעריף (NULL = לא ידוע), מטבע, `fromDate`, `untilDate`.
- `series_exceptions` — `seriesId`, `date`, `cancelled`, `hold` (בוטל אישור אוטומטי), שעות/תעריף חלופיים.
- מופעים מתוכננים לא נשמרים כשורות — מחושבים מהסדרה ומהחריגים, כמו באב-הטיפוס.

### הגדרות
ערכת צבעים, רטט, מצב שינה, אישור אוטומטי, התראות — בטבלת `work_local_preferences` הקיימת (מפתח/ערך). אין שינוי מבנה.

### הגנות
- הפעלת `exportSchema = true` ושמירת הסכמות בריפו.
- בדיקת מיגרציה 8→9 עם `MigrationTestHelper` על מסד סינתטי שמכיל כל סוג רשומה של RC16: סכומים ידניים, קבוצה, שני מטבעות, שעות בלבד, משולם ולא משולם.

## 2. גיבוי והעברה בין אנדרואיד לאתר
- הפורמט עולה ל-`formatVersion: 3` ומוסיף את השדות החדשים, הסדרות וההגדרות.
- נבדק בקוד: RC16 מקבל רק גרסאות 1–2 (`require(formatVersion in 1..2)`), כך שגיבוי של 2.0 **יידחה בבירור** בגרסה ישנה ולא ייובא חלקית.
- 2.0 ממשיך לקרוא גיבויים בגרסאות 1–2.
- האתר חייב לתמוך בגרסה 3 באותה השקה (השקה משותפת, כמתוכנן).

## 3. חוקים משותפים לשתי הפלטפורמות
קבצי JSON של מקרי בדיקה (קלט ← תוצאה צפויה) שרצים גם ב-Kotlin וגם ב-JS:
עיגול שעת סיום, משמרת לילה, תעריף חסר, בונוס (כולל קבוצה), קבלנות, השלמה מרוכזת (לא דורסת ולא נוגעת בקבלנות), יצירת סדרה ותצוגה מקדימה, חריגים, "זו והבאות", אישור אוטומטי וביטול, מצב שינה שחוצה חצות, שעון קיץ.
מקור האמת: מנוע אב-הטיפוס `design/v2-prototypes/shared/core.js`, שכבר מממש את כולם.

## 4. פירוק `MainActivity.kt` (לפני שינוי עיצוב)
- **העברה בלבד, בלי שינוי התנהגות**, בצעדים קטנים: קבצי מסכים ב-`ui/screens/` (בית, היסטוריה, רישום, הגדרות, אונבורדינג, AI, שיתוף).
- כל צעד מאומת בבדיקות הקיימות ללא שינוי (91 Debug / 73 Release ב-RC16, כולל צילומי Roborazzi) לפני הצעד הבא.
- שכבת חוקים טהורה (`domain/`) לחישובים — נבדקת בקבצי המקרים המשותפים.

## 5. עיצוב "כיס" בקוד
- `ui/theme/KisTheme.kt` מתוך `design/v2-design-system/tokens.json`: צבעים בהיר/כהה, 8 צבעי מקומות עבודה בגרדיאנט, טיפוגרפיה, ריווח, פינות, תנועה.
- גופנים Rubik + Secular One כקבצים בתוך האפליקציה (רישיון OFL ב-`docs/licenses`). Heebo נשאר גיבוי.
- רטט: `HapticFeedbackConstants` לפי טבלת מערכת העיצוב, עם מתג בהגדרות.

## 6. רקע, התראות ואישור אוטומטי
- ספרייה חדשה: WorkManager. משימה יומית אחת, אידמפוטנטית:
  1. מאשרת מופעים שהסתיימו (רק אם האישור האוטומטי פעיל; האינדקס הייחודי מונע כפילות).
  2. מחליטה על התראות: "הסיכום מוכן" (פעם בחודש), "יש משמרות בלי תעריף/סכום" (שבועי לכל היותר, רק כשיש).
  3. מצב שינה: התראה שנופלת בטווח נדחית לסופו, לא נמחקת.
- גם בפתיחת האפליקציה רץ אותו אישור (למקרה שהמשימה לא רצה).
- הרשאת התראות באנדרואיד 13+ מתבקשת רק כשמפעילים התראה, לא בהפעלה הראשונה.
- הטיימר החי הקיים (שירות חזית) נשאר כמו שהוא.
